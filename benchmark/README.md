# phase allocation benchmark

Real research data generated by running the phase allocator's **shipped CLI**
(`bin/phase-alloc.mjs`) end-to-end against a corpus of representative tasks
under three allocation configurations.

## Purpose

Capture empirical, measured data about how phase turns human intent into a
bounded Phase ISA allocation plan:

- which allocation **policy** is actually used (`model` / `heuristic` / `heuristic-fallback`),
- whether emitted plans are **structurally valid** and **budget-safe**
  (every resource clamped within the caller's ceiling, tools within the whitelist),
- **latency** of each path,
- **determinism** of the heuristic,
- **SLM behavior** on the live model path (including redundancy).

## Reproduction

```bash
# Requires: node >= 18, and (for the live-SLM path only) Ollama running with qwen2.5:0.5b
#   served at http://127.0.0.1:11434/v1

node benchmark/run-benchmark.mjs
```

The harness:

1. loads the task corpus from `benchmark/corpus.json` (9 tasks, 6 domains),
2. for each task × configuration, shells out to the real CLI with `--retries 0`,
   capturing the full JSON plan + wall-clock `hrtime` measurement + exit code,
3. validates every plan (structure, ceiling clamping, tool whitelist, agent,
   internal ISA↔allocation consistency, model-error/fallback consistency),
4. re-runs the heuristic on two tasks to confirm determinism,
5. re-runs three live-SLM tasks to observe model variability,
6. emits the dataset, summary CSV, raw per-run plans, and this report.

## Configurations under test

| id | policy | endpoint | expectation observed |
|---|---|---|---|
| `model-live` | `model` | `http://127.0.0.1:11434/v1` (Ollama) | live SLM allocation |
| `heuristic` | `heuristic` | — (offline) | deterministic heuristic |
| `fallback-down` | `model` | `http://127.0.0.1:8080/v1` (unreachable) | graceful heuristic fallback |

## Artifacts

| file | description |
|---|---|
| `corpus.json` | the task corpus (id, domain, complexity, scale) |
| `run-benchmark.mjs` | the harness / methodology |
| `data/dataset.jsonl` | canonical research dataset — one JSON object per run |
| `data/summary.csv` | tabular summary (run × policy × validity × budget × latency) |
| `data/raw/*.json` | full per-run `phase-alloc-servant-v1` plans |
| `report.md` | aggregate metrics / findings |

## Findings (from the committed run)

- **All three policies work and every plan validates.** `model-live` → `model`,
  `heuristic` → `heuristic`, unreachable endpoint → `heuristic-fallback`.
- **Budget safety holds.** All 32 scheduled/repeat runs stayed within ceilings:
  `context_tokens` 6600 (= `ceil(12000 × 0.55)`), `tokens` 24000, `wall_ms` 900000,
  `tool_calls` 40. The deterministic heuristic always allocates the smallest
  viable budget; only the live-SLM path can vary, and only within the ceiling.
- **Heuristic is deterministic.** Byte-identical allocation + ISA on re-run.
- **Latency** is the main differentiator: heuristic ~106ms, fallback ~1.4s
  (connection failure + retry bookkeeping), live model ~8.6s mean (Qwen 2.5B on
  CPU inference dominates).
- **SLM redundancy (real, now deduplicated).** On the live path the SLM emitted
  duplicated `GRANT` lines in 4/12 runs (e.g. `ci-pipeline::model-live` repeats
  `GRANT edit` / `GRANT test` five times). Harmless under set semantics, but
  noisy; a **deduplication pass** in `parseAllocatorAssembly` (GRANT set) and
  `allocationToAssembly` (no duplicate GRANT emission) now cleans the ISA.
